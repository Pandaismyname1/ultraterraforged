# 26.2 → 26.3: the worldgen rewrite

26.3 (released 2026-09-15) is the hardest hop by far. Mojang rewrote the world generation core. The earlier hops mostly rename things. This one removes the classes UTF is built on and replaces them with a compiled, buffer-based pipeline.

How big it is (measured, see [census/26.3-new.md](census/26.3-new.md)):

- **873 new compile errors in 74 files** on top of everything 26.2 already broke. For comparison, 1.20.1 → 1.21.1 is 136 errors, and 1.21.1 → 26.2 adds about 400.
- **Access widener:** 43 more entries die in 26.3, which leaves 55 of the 76 pointing at things that no longer exist (see [verification.md](verification.md#access-widener-check)).
- **Mixins:** 11 of the 21 common mixins lose their target method or class.
- **Datapack format:** the generated preset datapack has a new JSON shape.

None of it is a dead end. Every UTF feature has a place to hook in 26.3, and several hooks are *cleaner* than on 1.20.1. The rest of this page goes subsystem by subsystem: what UTF does today, what 26.3 replaced it with, and the concrete way to rebuild it. All signatures come from `javap` against the 26.3 jar (`~/.gradle/caches/fabric-loom/26.3/minecraft-merged.jar`). Where a solution is a design we haven't run yet, it says **verify**.

> **Registry name trap.** `Registries.FEATURE`, `Registries.MATERIAL_RULE`, `Registries.MATERIAL_CONDITION` and `Registries.CARVER` still exist in 26.3 but now mean the **datapack** registries of configured instances. The *type* (codec) registries are the new `*_TYPE` keys (`FEATURE_TYPE`, `MATERIAL_RULE_TYPE`, `MATERIAL_CONDITION_TYPE`, `CARVER_TYPE`).
>
> UTF registers into exactly these registries today, through `RegistryUtil.register(BuiltInRegistries.X, …)`:
> - `UTFFeatures` → `FEATURE` (6)
> - `UTFSurfaceRules` → `MATERIAL_RULE` (3, plus a `terrablender` rule when TerraBlender is present)
> - `UTFSurfaceConditions` → `MATERIAL_CONDITION` (11)
>
> Those `BuiltInRegistries` fields are removed in 26.3, so the compiler does flag them. The trap is the fix: the `Registries.X` *keys* with the same names still exist and look like the right replacement, but they name the datapack registries. Use `BuiltInRegistries.FEATURE_TYPE`, `MATERIAL_RULE_TYPE` and `MATERIAL_CONDITION_TYPE`, and the matching `Registries.*_TYPE` keys in the NeoForge `DeferredRegister`s.

## A. Terrain injection (the core of UTF)

**Today.** UTF's terrain comes from density functions in the preset noise router that are *markers* (`CellSampler.Marker`, `NoiseSampler.Marker`). `MixinRandomState` redirects `NoiseRouter.mapAll` in the `RandomState` constructor with a visitor. The visitor swaps each marker for a live, seeded instance: `CellSampler` is bound to the `GeneratorContext`, and `NoiseSampler` gets the world seed. `MixinNoiseChunk.wrapNew` then replaces each `CellSampler` with a per-chunk `CacheChunk` that reads the chunk's `Tile.Chunk`. `MixinNoiseChunk` also cuts `cellCountY` down to UTF's generation height, so noise above the terrain is never computed.

**26.3.** `NoiseRouter.mapAll`, `NoiseChunk.wrapNew`, `NoiseChunk.cellCountY` and the old `NoiseChunk` constructor are all gone. The replacements:

- `RandomState` owns a `DensityFunctionCompiler`. `RandomState.getSampler(df)` compiles lazily and caches. The compiler is built with a `CompileContext`, which is the anonymous class `RandomState$1` with a `final RandomState this$0` field.
- `NoiseChunk(RandomState, Beardifier, NoiseGeneratorSettings, FluidPicker, Blender, DensityVolume)` builds a `SamplerContext`. That context carries a `ContextMap` of *user fields*: vanilla puts `Beardifier.CONTEXT_KEY`, `Blender.CONTEXT_KEY`, `Blender.ALPHA_KEY` and `Blender.OFFSET_KEY` there.
- `ContextBoundSampler(ContextKey<? extends DensitySampler> key, DensitySampler fallback)` is how vanilla binds per-chunk data. At sample time it uses the sampler stored under `key` in the current `SamplerContext`, or the fallback when there is none. The beardifier is done exactly this way (`SimpleDensityFunction.BEARDIFIER`).

**Solution (mirrors how vanilla does the beardifier):**

1. **`CellSampler` and `NoiseSampler` become real 26.3 `DensityFunction`s.** They are still registered under `ultraterraforged:cell` and `ultraterraforged:noise_sampler` with `MapCodec`s, so the preset JSON keeps working.
   - `compileSampler(CompileContext ctx)`: get the `RandomState` from the context (step 2). For `NoiseSampler`, return a sampler seeded with `(int) randomState.seed()`, exactly as today.
   - For `CellSampler`, return `new ContextBoundSampler(UTFSamplerKeys.cell(field), directSampler)`. `directSampler` reads the `GeneratorContext` cache without a chunk cache. It replaces today's non-chunk path, and it is what `getBaseHeight`/structure queries and `SamplerContext.EMPTY_UNCACHED` hit.
   - `domainAxes()`: return the X|Z mask (`AXIS_X | AXIS_Z`) for 2D fields. The compiler then knows the value is constant along Y and evaluates it once per column. This replaces the hand-written `Cache2d`.
   - `range()`: return the field's real bounds as an `Interval`. The compiler uses it for clamping and cache decisions, so don't return an unbounded interval unless you have to.
   - `rewriteChildren(rule)`: leaf functions return `this`.
2. **Getting the `RandomState` inside `compileSampler`.** Add a small mixin on `net.minecraft.world.level.levelgen.RandomState$1` that shadows `this$0` and implements an UTF duck interface: `UTFCompileContext#randomState()`. Anonymous-class names are stable within a release now that the game is unobfuscated, but still check it with `javap` on every MC bump (the `checktargets.py` list covers it). Fallback if that is ever too fragile: keep a `WeakHashMap<CompileContext, RandomState>` filled by an `@Inject` at the `DensityFunctionCompiler.<init>` call in `RandomState.<init>`.
3. **Per-chunk cache.** Use `@WrapOperation` or `@ModifyArg` on `ContextMap$Builder.build()` inside `NoiseChunk.<init>` to also set `UTFSamplerKeys.cell(field) → CacheChunk sampler` for the chunk being generated. `CacheChunk` then implements `DensitySampler`:
   - `sampleValue(ctx, x, y, z)` reads the `Tile.Chunk`.
   - `sampleVolume(ctx, buffer, volume)` loops the volume's XZ and writes each column value across Y. Take the fast path when `volume.stepBlockY` covers the column. `DensitySampler.sampleVolumeNaive` is a fine first version.
   - Delete `MixinNoiseChunk.wrapNew` and the `NoiseChunk` shadows.
4. **Generation height cull.** `NoiseBasedChunkGenerator.createNoiseChunk(ChunkAccess, StructureManager, Blender, RandomState, NoiseSettings)` calls the private static `chunkVolume(ChunkAccess, NoiseSettings)`, which builds the chunk's `DensityVolume` from `NoiseSettings.minY()`/`height()` and the chunk's min X/Z. `@WrapOperation` that call inside `createNoiseChunk`, which has the `RandomState`. When it's an UTF world, return a volume whose `sizeY` stops at `generatorContext.lookup.getGenerationHeight(...)`. `lambda$buildTerrain$0` already sizes the section loop from `noiseChunk.volume().maxBlockY()`, so the rest follows. Keep the existing `iterateNoiseColumn` redirect on `NoiseSettings.height()`, because that method still exists.
5. **Fluid picker.** `MixinNoiseChunk.modifyFluidPicker` (lava level from the preset) moves to the `FluidPicker` argument of the same `new NoiseChunk(...)` call in `createNoiseChunk`, or to `NoiseBasedChunkGenerator.globalFluidPicker`. **Verify** which one the aquifer uses in 26.3.
6. **`initialize(RegistryAccess)`** (`MixinChunkMap` → `UTFRandomState.initialize`) can stay. `ChunkMap.<init>` lost the `Supplier<DimensionDataStorage>` and `ChunkProgressListener` parameters in 26.1, so the `@Inject` handler signature has to change. The `randomState` field is unchanged.

Why this is better than today: UTF stops relying on the visitor-over-the-whole-router trick and on NoiseChunk internals, and gets vanilla's volume buffers and column caching for free. Expect the chunk-generation benchmark to move. Re-measure with the `utf.render` tests before tuning.

## B. UTF's own density functions and the preset noise router

UTF registers `cell`, `clamp_to_nearest_unit`, `linear_spline` and `noise_sampler` (`UTFDensityFunctions`). Each needs the five abstract methods above. `clamp_to_nearest_unit` and `linear_spline` are pure math on a child: compile the child with `child.compileSampler(ctx)` (as vanilla's own ops and the 26.3 primer's example do), apply the function per value in `sampleVolume`, and implement `rewriteChildren` as `new X(rule.rewrite(child))`.

**`PresetNoiseRouterData` must be rebuilt on the 26.3 router shape:**

- `new NoiseRouter(temperature, vegetation, continents, erosion, depth, ridges, chunkSurfaceLevel, finalDensity)`. Only 8 fields remain.
- Aquifers move to `NoiseGeneratorSettings.aquifers` as `Aquifer.Config(barrier, floodedness, spread, lava, exclusion, surfaceLevel)`. Copy vanilla's `NoiseRouterData.overworldAquifers(...)`.
- Ore veins move out of the router into the material rule: `OreVeinRule(ore, rawOre, filler, rawOreChance, density, richness, fillerGap)`. The veinifier constants UTF reads through `OreVeinifier.VeinType.minY/maxY` are now `OreVeinRule.VeinType`.
- The helpers UTF widens in `NoiseRouterData` changed signature: `underground`, `entrances`, `postProcess(df, int, int)`, `noiseGradientDensity`, `yLimitedInterpolatable(df, df, int×5)`, `registerAndWrap` and `getFunction`. `SLOPED_CHEESE` is gone. `NoiseRouterData.overworld(HolderGetter, OverworldFunctionSet<ResourceKey<DensityFunction>>)` is now the single entry point that composes the router from a function set. Build an `OverworldFunctionSet` that points `offset`/`factor`/`jaggedness`/`depth`/… at UTF's keys and call `overworld(...)` through an invoker. That replaces most of the hand-copied vanilla code in `PresetNoiseRouterData`.

## C. Surface rules → material rules

UTF has 3 rules (`layered`, `noise`, `strata`) and 11 conditions (`any`, `biome_tag`, `erosion`, `height`, `height_modification_detection`, `mod`, `noise`, `river_bank`, `sediment`, `steepness`, `terrain`). It also has 4 mixins (`MixinSurfaceSystem`, `MixinContext`, `MixinSurfaceRules$BiomeConditionSource`, and the `buildSurface` HEAD/TAIL pair in `MixinNoiseBasedChunkGenerator`) plus 20 access-widener entries on `SurfaceRules$Context`.

**26.3 API:**

```java
interface MaterialRule      { RuleEvaluator      compile(MaterialRuleContext ctx); MapCodec<? extends MaterialRule> codec(); }
interface MaterialCondition { ConditionEvaluator compile(MaterialRuleContext ctx); MapCodec<? extends MaterialCondition> codec(); }
interface RuleEvaluator     { BlockState tryApply(int x, int y, int z); }   // null = no match
interface ConditionEvaluator{ boolean test(); }
```

`MaterialRuleContext` has public getters for everything the old `Context` fields gave UTF through the access widener:

- position: `blockX()`, `blockY()`, `blockZ()`, `blockPos()`
- depth and water: `stoneDepthAbove()`, `stoneDepthBelow()`, `surfaceDepth()`, `waterHeight()`
- biome and level: `getBiome()`, `possibleBiomes()`, `getSeaLevel()`, `getMinSurfaceLevel()`
- noise and random: `getNoiseSampler(key, is3d)`, `getOrCreateRandomFactory(id)`, `getDensitiesInChunk(df, …)`
- new: `surfaceGradientX()`, `surfaceGradientZ()`, `resolveAnchorY(anchor)`

Two things UTF uses are not exposed:

- **The `RandomState`**, a private field. UTF needs it to reach its `GeneratorContext`. It's used by `BiomeTagCondition`, `CellCondition`, `LayeredSurfaceRule` and `StrataRule`.
- **The `ChunkAccess`**. There's no field for it at all. `HeightModificationDetection` reads `chunk` at `blockY`, and `StrataRule` reads the chunk's build-height bounds.

**Solution:**

1. **Delete most of the access widener.** Add one `@Accessor` mixin on `MaterialRuleContext` for `randomState` (and `system` if strata needs it). All 20 `SurfaceRules$Context` entries and `SurfaceSystem.seaLevel` go away. For the chunk:
   - `StrataRule`'s build-height bounds can come from `ctx.resolveAnchorY(VerticalAnchor.bottom())` / `VerticalAnchor.top()`.
   - For `HeightModificationDetection`, keep UTF's existing thread-local pattern: `SurfaceRegion` today holds the `WorldGenRegion`, so have it also hold the `ChunkAccess`. Set it at HEAD of the private `NoiseBasedChunkGenerator.buildSurface(ChunkAccess, NoiseChunk, …)` (see step 6) and clear it at TAIL.
2. **Port each condition** from `LazyXZCondition`/`ThresholdCondition` to a record implementing `MaterialCondition`:
   - `compile(ctx)` resolves the `GeneratorContext` once, through the accessor.
   - It returns an evaluator that reads `ctx.blockX()`/`blockZ()` on each `test()` and memoizes per XZ. `MaterialRuleContext` updates XZ before Y, the same order as the old lazy conditions.
3. **Port the rules:**
   - `strata` and `layered` implement `MaterialRule.compile` and return `(x, y, z) -> state-or-null`.
   - The strata cache that `MixinSurfaceSystem` added (`getOrCreateStrata` keyed per cache id) moves to a mixin on `MaterialSystem`, which is still owned by `RandomState` (`RandomState.surfaceSystem()` now returns `MaterialSystem`).
   - The strata random came from `randomState.random.fromHashOf("ultraterraforged:strata")`. Use `ctx.getOrCreateRandomFactory(UTFCommon.location("strata"))` instead. Check whether it produces the same stream: if it doesn't, strata layouts will change for existing seeds, and the golden fingerprints must be regenerated deliberately.
4. **Delete `MixinContext` and `MixinSurfaceRules$BiomeConditionSource`.** Both exist to short-circuit biome conditions using the biomes around the chunk. Vanilla does this itself: 26.2 added a `Set<Holder<Biome>>` of possible biomes to `buildSurface` and the surface context, and in 26.3 `BiomeCondition.compile` returns a constant `true`/`false` evaluator when the set proves the result (`canNeverMatch`/`willAlwaysMatch`). `SurfaceRegion` stays, repurposed to carry the chunk (step 1).
5. **Rewrite `PresetSurfaceRuleData` / `PresetSurfaceLayerData`** (199 of the 873 errors) mechanically. `SurfaceRules.ifTrue/sequence/state/isBiome/stoneDepthCheck/yBlockCheck/yStartCheck/waterBlockCheck/steep/hole/abovePreliminarySurface/verticalGradient/temperature/bandlands` all exist with the same names on `MaterialRules`. `noiseCondition(key, min[, max])` becomes `noiseCondition2d` (or `noiseCondition3d`). Bonus: material rules and conditions are datapack registries now, so the preset can register named, reusable pieces (for example `ultraterraforged:strata`) and reference them by id. That keeps the generated JSON much smaller.
6. **`MixinNoiseBasedChunkGenerator.buildSurface` HEAD/TAIL.** The public 4-argument `buildSurface` is gone. Move the HEAD/TAIL pair that sets `SurfaceRegion` to the private `buildSurface(ChunkAccess, NoiseChunk, RandomState, BiomeManager, Set<Holder<Biome>>, MaterialRule)`, called from `lambda$buildTerrain$0`. It's the only surface entry point now. Carvers also run material rules (`applyCarvingMask(…, MaterialRule, …)`), so wrap `generateCarvers` the same way, or the chunk thread-local will be null during carving.

## D. Features

UTF registers 6 features (`bush`, `chance`, `disk`, `erode_snow`, `swamp_surface`, `template`), each as `Feature<Config>` with a nested config record. `DiskFeature` reuses vanilla's `DiskConfiguration`, which 26.3 deletes.

**26.3:** `Feature` is an interface; a feature instance *is* its configuration. The datapack registry `worldgen/feature` holds instances, and `worldgen/feature_type` holds their `MapCodec`s.

**Solution, per feature:**

- Turn `XFeature extends Feature<XFeature.Config>` into `record XFeature(<config fields>) implements Feature`.
- `codec()` returns a static `MapCodec` built from the old config codec. The JSON stays the same except for the wrapper: there is no separate `config` object anymore. **Verify** against a vanilla 26.3 feature JSON from the generated data.
- `place(WorldGenLevel level, ChunkGenerator generator, RandomSource random, BlockPos origin)` replaces `place(FeaturePlaceContext)`.
- Register the codec in `BuiltInRegistries.FEATURE_TYPE`, not `FEATURE` (see the trap above).
- `DiskFeature` gets its own fields (state provider, target predicate, radius `IntProvider`, half-height). Vanilla 26.3 still ships a `disk` feature, so compare the two and consider dropping UTF's copy.

**Preset datagen:**

- `PresetConfiguredFeatures` (107 errors) and `PresetPlacedFeatures`: `ConfiguredFeature` values become `Feature` values. `FeatureUtils.register(ctx, key, Feature.X, config)` becomes `ctx.register(key, new XFeature(...))`.
- Vanilla's `random_selector`/`random_patch`/`simple_block`, and the flower feature UTF copies, were reshaped:
  - 26.1 removed `random_patch`, `flower` and `no_bonemeal_flower`.
  - 26.2 added `sequence`, `template` and `weighted_random_selector`.
  - Use the generated 26.3 vanilla JSON as the reference: run `docs/porting/tools/vanilla-datagen.sh 26.3` and look under `data/minecraft/worldgen/feature`.
- `MixinBiomeGenerationSettings`: the `flowerFeatures` accessor is dead since 26.1, and the `features` accessor type must be checked again.

## E. Placement modifiers and chance modifiers

UTF has 6 placement modifiers (`dimension_filter`, `fast_poission`, `legacy_count_extra`, `macro_biome_filter`, `noise_filter`, `terrain_filter`) plus the `ChanceModifier` system.

- `PlacementFilter` still exists. Filters that only override `shouldPlace(ctx, random, pos)` only need `type()` replaced by `MapCodec<? extends PlacementModifier> codec()`.
- Generators (`fast_poission`, `legacy_count_extra`) change from returning `Stream<BlockPos>` to pushing positions: `modify(PlacementContext ctx, RandomSource random, BlockPos pos, Consumer<BlockPos> out)`. The change is mechanical: every `stream.add(p)` / `Stream.of(...)` becomes `out.accept(p)`, and it's also faster.
- `PlacementModifierType` is gone. Register the `MapCodec` directly in `BuiltInRegistries.PLACEMENT_MODIFIER_TYPE`, whose values are `MapCodec`s now (see `PlacementModifierTypes.bootstrap`).
- `random_offset` became `offset`; new ones are `random_chance`, `randomly_selected` and `cuboid`. Preset data that used vanilla modifiers must use the new ids.

## F. Structures

- **Structure rules** (`MixinStructure` → `isValidBiome` HEAD): retarget to `Structure$GenerationContext.isValidBiome(Structure$GenerationStub)`. It's an instance method now, so the handler gets `this` as the context. The body is unchanged.
- **Structure-set options.** UTF's structure editor reads and writes `StructurePlacement.salt/frequency/frequencyReductionMethod/exclusionZone/locateOffset` through the access widener. In 26.3 those live on `AbstractSpreadingStructurePlacement`, with public accessors `frequency()`, `exclusionZone()`, `frequencyReductionMethod()`, …. Random-spread and concentric-ring placements extend it; the new `dimension_origin` placement doesn't. Change `StructureSettings`/`StructureOptions` to `instanceof AbstractSpreadingStructurePlacement` and drop those 6 access-widener lines. If the editor needs to *build* modified placements, check whether `RandomSpreadStructurePlacement` still has a public constructor taking these values.

## G. Carvers

UTF configures caves and canyons in the preset (`PresetConfiguredCarvers`, `CaveCarverConfiguration`, `CanyonCarverConfiguration`, `CarverDebugSettings`, `LegacyCanyonYScale`, `LegacyCarverHeight`).

- 26.3 merges configuration into the carver: `new CaveWorldCarver(float probability, HeightProvider y, IntProvider…, FloatProvider…, boolean, FloatProvider×5)`, and the same for canyons. The registries are `worldgen/carver` (instances) and `worldgen/carver_type` (codecs).
- `CarverDebugSettings` and the replaceable-blocks tag field are gone. The replaceable check is now done by the material system, so the `OVERWORLD_CARVER_REPLACEABLES` tag reference in the preset has to go too.
- `LegacyCanyonYScale` (FloatProvider) and `LegacyCarverHeight` (HeightProvider) are unaffected by the carver change. They only need the 26.1 valueprovider change: `FloatProvider` is an interface with `min()`/`max()`/`MapCodec codec()`, and `FloatProviderType` is gone.

## H. Chunk generator hooks, spawn, climate

- **`MixinNoiseBasedChunkGenerator.fillFromNoise` redirect** of `NoiseSettings.height()`: this is the height cull, now handled by A.4. Delete the redirect.
- **`addDebugScreenInfo`** gained a `SamplerContext` parameter. Update the handler signature.
- **`MixinChunkStatus`** (the structure-starts and features hooks that queue and drop UTF's tile cache) targets `ChunkStatusTasks.generateStructureStarts` and `generateFeatures`. Both still exist in 26.3 with the 1.21 signature, so no change is needed beyond the 1.21.1 retarget (see [1.21.1.md](1.21.1.md#chunk-status-hooks)). The `generateNoise`/`generateSurface`/`generateCarvers` tasks became `buildTerrain`; UTF doesn't hook those.
- **Spawn.** `Climate.findSpawnPosition`, `Climate$Sampler.findSpawnPosition` and `MinecraftServer.setInitialSpawn`'s call to it are gone. `setInitialSpawn` now calls `ChunkGenerator.getOrigin(RandomState)`, which `NoiseBasedChunkGenerator` implements with `NoiseSpawnFinder`. Replace `MixinSpawnFinder` and the server spawn redirect with **one** `@Inject(HEAD, cancellable)` on `NoiseBasedChunkGenerator.getOrigin`, returning UTF's spawn chunk when the `RandomState` has an UTF context. That's simpler than today.
- **Climate.** `Climate.Sampler` is now a record of six `DensitySampler.Bound`s, built by `RandomState.createClimateSampler(SamplerContext)`. `MixinClimateSampler` (`sample(III)`) still has a target. The TerraBlender mixins (`terrablender.*`) patch TerraBlender's own injections into these classes, so rebuild them against TerraBlender `26.3-26.3.0.0.7` and don't carry them over. TerraBlender 26.3 also replaces `SurfaceRuleManager` with **`MaterialRuleManager`** (`addRules(RuleCategory, namespace, ResourceKey<MaterialRule>)`), which is what `TBSurfaceRules` has to target now.
- **`BiomeSource`**: if UTF ever subclasses it, `getNoiseBiome` is replaced by `createResolver(Climate.Sampler)`. UTF currently doesn't.

## I. Codec plumbing

- **`KeyDispatchDataCodec`** is removed (20 compile errors). Everywhere UTF wrote `KeyDispatchDataCodec.of(CODEC)`, return the `MapCodec` directly. This applies to UTF's density functions, surface rules and conditions, and UTF's own dispatch registries if they borrowed the pattern: `Noise`, `Domain`, `CurveFunction`, `StructureRule`, `ChanceModifier`, `TemplatePlacement`, `TemplateDecorator`, `BiomeModifier`.
- **Registry codecs** moved from `net.minecraft.resources` to `net.minecraft.core.registries.codec`. This covers `RegistryFileCodec`, `RegistryFixedCodec` and `HolderSetCodec`; the old `RegistryCodecs` helpers now live there too: `homogeneousList` → `RegistryCodecs.holderSet(key[, codec[, inline]])`, and `RegistryFileCodec.create(key, codec, allowInline)`. This touches `Noise.java:11` and `PresetBiomeModifierData`.

## J. Preset datagen plumbing

These breaks sit in UTF's runtime datagen path (`Preset.buildPatch` → `UTFDataGen` → `PresetPacks`) rather than in worldgen logic:

- **`RegistrySetBuilder.add(key, Lifecycle, bootstrap)`** is gone. Use `add(key, SingleRegistryBootstrap)`, or `add(MultiRegistryBootstrap)` for bootstraps that register into several registries at once. `BootstrapContext.register(key, value, Lifecycle)` is gone too; use `register(key, value)`. `Preset.buildPatch` adds 14 registries: change the method references, not the bodies.
- The registry keys `CONFIGURED_FEATURE` and `CONFIGURED_CARVER` are gone. `Preset.java:68,71` switches to `Registries.FEATURE` and `Registries.CARVER` (here the datapack meaning is the right one).
- **`VanillaRegistries.createLookup()`** → `createWorldLookup()` (plus `createReloadableLookup(provider)` for the new reloadable layer). Callers: `ServerPresets:47` (the dedicated-server base lookup) and several tests.
- `RegistryDataLoader.WORLDGEN_REGISTRIES` → `WORLD_REGISTRIES`, and `RegistryLayer.WORLDGEN` → `WORLD`. The Fabric `DataGenUtilImpl` iterates the datapack registries to write them; check which list it reads.
- On NeoForge, `DataPackRegistryEvent.NewRegistry` → **`NewDatapackRegistryEvent`**, with `worldRegistry(key, codec)` for UTF's 5 registries. Fabric adds `DynamicRegistries.registerReloadable`, but UTF's registries belong in the world layer, which is unchanged.
- **Packs:** `BuiltInPackSource.createVanillaPack(PackResources)` → `createVanillaPack(Pack.ResourcesSupplier)`, `Pack$ResourcesSupplier.openPrimary/openFull` → `openMetadata/openResources`, and `VanillaPackResources` no longer implements `PackResources`. This hits `UTFBuiltinPackSource` (a no-op today, see [1.21.1.md](1.21.1.md)) and possibly `MixinServerPacksSource`. The `createPackRepository(Path, DirectoryValidator)` target still exists (checked).

## K. Noise parameters and noise settings

- `NormalNoise.NoiseParameters` is gone. `Registries.NOISE` holds `NormalNoise` itself, built with `NormalNoise.builder().setBaseOctave(firstOctave).setAmplitudeModifier(i, a)….build()`. The JSON renames `firstOctave` → `base_octave` and `amplitudes` → `amplitude_modifiers`, and adds `octave_count`/`base_amplitude`/`normalize`. This affects `PresetNoiseParameters`, `PresetNoiseData`, the `NoiseParameters` references in `NoiseCondition` and `TBNoiseRouterData`, and `MixinRandomState`'s `NoiseHolder` visitor, which disappears with A.
- The builder has `setLegacyNormalization()`. When UTF re-registers *vanilla* noises (it copies vanilla's noise registry into the preset), use exactly what vanilla 26.3 uses for that noise; copy it from `tools/vanilla-datagen.sh 26.3` output under `worldgen/noise`. Otherwise caves and aquifers shift for the same seed.
- `NoiseSettings.create(minY, height, sizeH, sizeV)` → `create(minY, height)`. The cell sizes moved into `interpolated(...)` density functions (`PresetNoiseGeneratorSettings:33`; `CellSampler`'s `getCellHeight()` use).
- `spawn_target` entries are `SpawnTargetPoint(Map<density function, range>)`, keyed by density-function ids such as `minecraft:overworld/continents`. UTF's climate functions need registered ids for this; `PresetNoiseGeneratorSettings` builds the spawn target today.
- **Biomes:** mob spawns became the environment attribute `minecraft:gameplay/natural_mob_spawns`, and the biome JSON loses `spawners`/`spawn_costs`. `PresetBiomeData` copies vanilla biomes, so rebuild it from the 26.3 vanilla biome JSON (again, `vanilla-datagen.sh`).

The preset datapack is written by codecs, so JSON *key* renames (such as `argument1/argument2` → `left/right` on binary density functions) are automatic once the code compiles. What doesn't come for free is anything hand-copied from vanilla.

## L. GUI

26.3 moves rendering to the `com.mojang.renderpearl` API. For UTF, this only affects the terrain preview texture: `TerrainPreview` uploads a `NativeImage` through `DynamicTexture`, and `GuiGraphicsExtractor.blit` takes `renderpearl` pipelines and texture views. Widgets and screens are unaffected beyond the 26.1/26.2 renames (`GuiGraphicsExtractor`, `extractRenderState`, `MenuTabBar`; see [26.1.md](26.1.md) and [26.2.md](26.2.md)). 26.3 also switches key and mouse input to SDL scancodes, with mouse buttons numbered 1/2/3. Check the preview's drag and zoom handlers and the editor's ctrl+click reset.

## Strategy options

1. **Native 26.3 port (recommended).** Do A → C → B → D–G → H–L in that order. A and C are the architecture; the rest is mechanical. The terrain tests (`TerrainSensitivityTest`, golden fingerprints) can run as soon as A and B compile, because they're headless.
2. **A version bridge, if 26.2 and 26.3 must ship from one Stonecutter tree.** Put UTF's four vanilla touch points behind small internal interfaces:
   - *field source*: the 2D terrain value at (x, z)
   - *surface condition/rule*: "evaluate at x, y, z with a generator context"
   - *feature placer*
   - *placement filter*
   Keep one adapter per MC generation (≤26.2 and ≥26.3). The preset datagen classes still split per version, since their inputs are vanilla builders. Stonecutter file swaps (`//? if >=26.3`) at class granularity work better here than line-level conditionals: the 26.3 code doesn't resemble the old code.
3. **Skip 26.3 until the ecosystem settles.** Not recommended as a long-term plan, but reasonable while TerraBlender and the loaders are still on beta builds for 26.3 (NeoForge is `26.3.0.23-beta`; TerraBlender is at `26.3.0.0.7`).
