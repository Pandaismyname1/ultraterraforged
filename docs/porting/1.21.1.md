# 1.20.1 → 1.21.1

The first hop is moderate: **136 compile errors in 79 files** ([census/1.21.1.md](census/1.21.1.md)), almost all mechanical. UTF's heavy worldgen mixins (NoiseChunk, RandomState, SurfaceSystem, SurfaceRules.Context, Climate, NoiseBasedChunkGenerator) keep their targets. The loader side is the bigger job: Forge → NeoForge, see [neoforge.md](neoforge.md).

The build stays on the remapping toolchain (Mojang mappings, `dev.architectury.loom`) and moves to Java 21 ([toolchain.md](toolchain.md#1201--1211-still-the-remapping-toolchain)).

## Mixins

The target check ([census/mixin-targets.txt](census/mixin-targets.txt), from `tools/checktargets.py`) shows what moves in 1.21.1:

### Chunk status hooks

`MixinChunkStatus` targets the intermediary/SRG names of two 1.20.1 lambdas (`method_39464`/`m_289181_` = structure starts, `method_51375`/`m_279978_` = features). In 1.21 the status logic moved to **named static methods**:

```
ChunkStatusTasks.generateStructureStarts(WorldGenContext, ChunkStep, StaticCache2D<GenerationChunkHolder>, ChunkAccess) → CompletableFuture<ChunkAccess>
ChunkStatusTasks.generateFeatures(WorldGenContext, ChunkStep, StaticCache2D<GenerationChunkHolder>, ChunkAccess) → CompletableFuture<ChunkAccess>
```

Retarget both injections there. These signatures are unchanged through 26.3 (checked), so this retarget survives every later hop.
- The level comes from `WorldGenContext.level()`.
- The center chunk is the `ChunkAccess` parameter.
- The structure-starts TAIL currently runs when the returned future is created, not when it completes. That was already true in 1.20.1, so it's no behaviour change. Still, **verify** whether `generateStructureStarts` completes synchronously; if it doesn't, move "fast cell lookups on" into a `thenApply`.

## How the port went (2026-09-28, branch `1.21.1`)

Done as planned above, with these differences and findings:

- **Dispatch codecs:** instead of converting 121 codecs to `MapCodec`, `data/UTFCodecs` adapts them where they're
  dispatched: a map codec is used as is, any other codec is written under a `"value"` key, as DFU 6 did. Preset JSON and
  share codes stay byte-identical, and 26.3's removal of `KeyDispatchDataCodec` will touch one class.
- **`buildPatch` has two traps not in the census:**
  - It looks up every patched registry in the lookup it starts from, and Fabric's lookup lacks UTF's datapack registries
    (NeoForge's has them), so creating a world failed with `Registry ultraterraforged:worldgen/structure_rule not
    found`. `UTFRegistries.patchBase` adds empty ones, and leaves out registries it has no codec for (the NeoForge client failed on `neoforge:structure_modifier`: "No cloner for ...").
  - A patch's holders only serialize through `provider.createSerializationContext(ops)`; `RegistryOps.create(ops,
    provider)` makes every holder "not valid in current registry set". The Fabric registry writer and the tests use the
    former.
- **`MixinRegistryDataLoader`:** a `@Redirect` of the `loadElementFromResource` call in `loadContentsFromManager`, whose
  arguments include both the `Resource` and its `RegistrationInfo`; no MixinExtras needed.
- **`MixinCreateWorldScreen`:** adds its own `tick()` override, which also ticks the Terrain tab (`Tab.tick` is gone).
- **`UTFBuiltinPackSource`** deleted: it read a folder that doesn't exist.
- **NeoForge:**
  - `RegistryUtil.register` is now the platform method; NeoForge queues entries and writes them in `RegisterEvent`,
    and `DeferredRegistry` is gone. `getWritable` and `getBiomeModifierRegistry` are gone.
  - Biome modifiers: one NeoForge modifier, `ultraterraforged:preset` (`data/ultraterraforged/neoforge/biome_modifier/
    preset.json` in the jar), applies the preset's modifiers at `AFTER_EVERYTHING`, reading UTF's registry from
    `ServerLifecycleHooks.getCurrentServer()` (set before NeoForge runs modifiers). `BiomeGenerationSettingsBuilder.
    getFeatures(step)` replaces the accessor mixin.
  - `MixinMinecraftServer` no longer targets a lambda: the template manager is made on first use, and `/reload`
    reaches it through `AddReloadListenerEvent`.
  - `MixinTagsProvider` deleted: NeoForge 21.1 null-checks the `ExistingFileHelper` itself.
  - The access widener becomes an AT in Mojang names through `remapJar { atAccessWideners }`.
- **Tests:** 182, fingerprints unchanged. Only test code changed: the `tags/block` folder, `getOrThrow`, and
  `RegistrationInfo`.
- **Performance mods:** C2ME OpenCL needs Java 25; see [performance-mods.md](performance-mods.md#java-25).
