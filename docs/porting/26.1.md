# 1.21.1 → 26.1 / 26.1.2

This hop covers eight Minecraft releases (1.21.2 → 1.21.11 → 26.1), the switch to an unobfuscated game, and Java 25. For UTF it's broad but shallow: **309 new compile errors in 60 files** ([census/26.1-new.md](census/26.1-new.md)), on top of the 1.21.1 ones. There's no architectural change to the worldgen hooks, but there are a few **silent** semantic changes the compiler won't catch (called out below).

**26.1 and 26.1.2 are the same target.** The class dumps differ by one added GUI method, the compile census is identical, and the hotfixes changed no worldgen or pack format. Build against 26.1.2 and declare `>=26.1 <26.2` (Fabric: `"minecraft": ">=26.1 <26.2"`; NeoForge: `[26.1,26.2)`). 26.1.1 wasn't dumped, but the wiki lists it as a bug-fix hotfix.

Toolchain: `dev.architectury.loom-no-remap`, no mappings, access widener namespace `official`, daemon JVM 25, and a hand-written NeoForge AT. See [toolchain.md](toolchain.md#1211--261-the-unobfuscated-toolchain). **Spike `@ExpectPlatform` first.**

## Silent changes (compile fine, behave differently)

1. **`getMaxY()` is one less than `getMaxBuildHeight()`** (1.21.2: the top is now inclusive). Sites:
   - `BlockUtils.java:50`: `Math.min(world.getMaxBuildHeight() - 1, …)` becomes `Math.min(world.getMaxY(), …)`.
   - `StrataRule.java:71-72`: `height = max - bottom + MARGIN*2` becomes `getMaxY() + 1 - bottom + …`. If this isn't changed, the strata stack shifts by one block and the golden fingerprints move.
   - The clienttest `getMaxBuildHeight` loops.
2. **The noise router's `initial_density_without_jaggedness` became `preliminary_surface_level` (1.21.9), with different semantics.** The old field was a *density*, and vanilla searched it for the surface. The new one is a *Y level*; vanilla wraps the old density in `find_top_surface(density - 0.390625, cell_height 8, …)` (see the generated 26.1.2 `noise_settings/overworld.json`). UTF already knows its terrain height per column, so feed its height field (in blocks) straight in rather than wrapping a density in `find_top_surface`. That's exact and cheaper. It also replaces what `MixinNoiseChunk.computePreliminarySurfaceLevel` does today: with the router value correct, that redirect has nothing left to fix (**verify** against the aquifer and surface-depth output). The AW entry `NoiseChunk.initialDensityNoJaggedness` is dead from 26.1.
3. **`NativeImage` pixels are ARGB** (1.21.2): `setPixelRGBA` is private, and `setPixel(x, y, argb)` uses ARGB order. The preview colours are packed as ABGR today: `RenderMode.rgba` (`RenderMode.java:220`) builds `r + (g << 8) + (b << 16) + (255 << 24)`, which `TerrainPreview:162` passes to `setPixelRGBA`. Switch the packing to `ARGB.color(255, r, g, b)` when moving to `setPixel`, or the red and blue channels swap.
4. **GUI text colours need alpha** (1.21.6): `0xFFFFFF` renders invisibly. Use `0xFFFFFFFF` / `ARGB.opaque(c)`. Every `drawString`/`text` colour in `TerrainPreview`, `Label` and `SavePresetScreen` needs checking.
5. **Registry API renames (1.21.2)** compile against the wrong overload in places:
   - `registry.get(ResourceLocation)` → `getValue`, and `get(key)` now returns an `Optional<Holder.Reference>`.
   - `registryOrThrow` → `lookupOrThrow`.
   - `holders()` → `listElements()`.
   - `getTag` → `get(TagKey)`.

   UTF mostly uses `HolderGetter`/`lookupOrThrow` already. Grep for `.get(` on `Registry` types anyway.
6. **`Mth.clampedLerp` argument order changed in 1.21.11.** UTF doesn't call it today (grepped). Keep it that way, or check the order if the noise code ever starts using it.
7. **`MixinSpawnFinder` still applies to every world** (it's been that way since 1.20.1). That's a behaviour question, not a porting one. It goes away naturally in 26.3 (see [26.3.md](26.3.md#h-chunk-generator-hooks-spawn-climate)).

## Mixins

- `MixinRegistryDataLoader`: in 26.1 the element loading moved to `ResourceManagerRegistryLoadTask.lambda$load$2(…, Resource)`. See the fix design in [1.21.1.md](1.21.1.md#others). `RegistryDataLoader.load` is now async (`CompletableFuture`).
- `MixinNoiseChunk`: the constructor is unchanged until 26.3, but the `initialDensityNoJaggedness` shadow is dead (see above). Drop it together with the `computePreliminarySurfaceLevel` redirect.
- `MixinSurfaceRules$BiomeConditionSource` and `MixinContext`: unchanged in 26.1; they change in 26.2.
- `MixinCreateWorldScreen`: `init`, `onCreate` and `TabNavigationBar$Builder.addTabs` still match in 26.1. `CreateWorldScreen.openFresh` takes a `Runnable` (1.21.9; the clienttest uses it).
- Fabric `MixinPresetEditor` (`Map.of` in `<clinit>`): re-check with `javap` that vanilla still builds `EDITORS` with a two-entry `Map.of`. If it doesn't, target the new call.
- Lambda-named targets (Fabric `method_29440`, the Forge-era `lambda$…`): intermediary names **no longer exist** from 26.1. Replace them with reload listeners (see [neoforge.md](neoforge.md)).

Run `tools/checktargets.py` and `tools/checkaw.py` after the bump. The 26.1 rows in [census/mixin-targets.txt](census/mixin-targets.txt) are the reference.

## GUI

Beyond the renames:
- **Render-state GUI** (1.21.6): drawing is recorded and then rendered. `pose()` is a 2D `Matrix3x2fStack`, `blit` takes `RenderPipelines.GUI_TEXTURED` (verified in the 26.1 jar) plus the texture size, and scissor calls are recorded like everything else.
- The preview texture:
  - `new DynamicTexture(() -> "ultraterraforged:preview", image)`.
  - `TextureManager.register(String, DynamicTexture)` (which returned a generated id) is gone. Use `register(Identifier, AbstractTexture)` with a fixed id such as `ultraterraforged:preview/<n>`, and `release` it when the tab closes.
  - `texture.upload()` after pixel writes is unchanged.
- The preview renders on the `UTF-Preview` executor and hands back through `Minecraft.getInstance().execute`. From 26.1, **`Font` measuring and splitting must run on the render thread only** (from the EMI port). Keep all text layout inside `extractRenderState`.
- `AbstractSelectionList` entries implement `extractContent(GuiGraphicsExtractor, int, int, boolean, float)` (`WidgetList.Entry`).

## World creation

- World generation settings became `SavedData` in 26.1, and the world folder was restructured (26.1 "File Fixer Upper").
  - `ServerPresets.installIfNewWorld` decides "new world" by checking for `level.dat`. `LevelResource.LEVEL_DATA_FILE` still exists in 26.3, but check that a 26.1 world's root still has `level.dat` before trusting it. The dedicated-server smoke test (`smoke2.sh`) covers this.
  - The preset datapack still goes in `<world>/datapacks/`.
- `WorldCreationContext`/`WorldCreationUiState`: `setAllowCommands` (1.21.1). `WorldCreationContext` takes `InitialWorldCreationOptions` (1.21.2).

## Datapack

- The pack format uses the `min_format`/`max_format` scheme (1.21.9; data `101.1` in 26.1). UTF generates `pack.mcmeta` with `PackMetadataGenerator` from `SharedConstants`, so it follows automatically.
- The generated preset JSON is produced by codecs, so key renames (`preliminary_surface_level`, biome `attributes`, dimension type fields) follow the code. The fixture presets in `common/src/test/resources/fixtures` are UTF-format presets, not vanilla JSON, so they're unaffected.
- `WorldOptions` JSON: `generate_features` → `generate_structures` (26.1). This only matters if UTF writes world options itself (it doesn't).

## How the port went (2026-09-28, branch `26.1`)

Done as planned above; differences and findings:

- **`@ExpectPlatform` works under loom-no-remap**: the built jars call `platform.<loader>.*Impl` (checked with `javap`).
- **NeoForge access transformer:** `docs/porting/tools/aw2at.py` writes `neoforge/src/main/resources/META-INF/accesstransformer.cfg`
  from the widener, and `neoforge:checkAccessTransformer` fails the build when they differ. Dead at 26.1 and pruned:
  `NoiseChunk.initialDensityNoJaggedness`, `Beardifier.pieceIterator`/`junctionIterator`, `Biome.getTemperature`.
- **Preliminary surface level:** instead of UTF's height field, the router gets `findTopSurface(old density - NOISE_ZERO,
  top of the world, bottom, 8)`, the search `NoiseChunk` did itself before 1.21.9, so the value is exactly 1.21.1's
  (UTF's density never passes the threshold above its terrain). The `computePreliminarySurfaceLevel` redirect is gone.
- **No more pinned constructors or lambda names:** `MixinChunkMap` captures nothing and shadows `level`;
  `MixinResourceManagerRegistryLoadTask` is matched by its two calls (`method = "*"`); the feature template manager is
  made lazily in a common mixin and notices `/reload` itself (a new server resource manager), so neither loader needs a
  reload hook (Fabric's `method_29440` target no longer exists without intermediary names).
- **Silent GUI change not in the list above:** vanilla's `AbstractSliderButton` now calls a protected `setValue(double)`
  on click, drag and keys, which UTF's `Slider.setValue` overrode; renamed `setSliderValue`.
- **Feature order cycle (plains/river):** 26.1 put `patch_bush` before `trees_plains` in plains but after `trees_water`
  in rivers; UTF's modifier replacing both with one feature made vanilla refuse to generate ("Feature order cycle
  found"). `BiomeModifiers.distinctReplacements` copies a replacement once per feature it replaces. Check this on every
  version: vanilla reorders vegetation often.
- **Biome flower list:** `flowerFeatures` became `boneMealFeatures` (features tagged `can_spawn_from_bone_meal`); the
  Fabric biome modifiers rebuild it and `featureSet` through `@Mutable` accessors.
- **Tests on Java 25:** Mockito 5.24 (its Byte Buddy reads Java 25 classes) and `TestBootstrap` resets each registry's
  tag set before freezing again (`MappedRegistry.freeze` refuses a registry whose tags are already bound).
- `UTFBiomes`, `VanillaTerrainProvider` and `VolatileAirBlock` were unused and are deleted.
